# QUIC recovery and congestion readout - SNAPSHOT

SNAPSHOT. Every figure below was produced by TlsQuicRecoveryReadout from a live
connection driven through induced loss, two probe timeouts and a blackout long
enough to establish RFC 9002 s7.6's persistent congestion. NONE of it has an
external source in the sense the Brave capture is one. Per A2's standing rule, a
checked-in number with no external source is a snapshot and is labelled one.

THE VERDICT COLUMN SCORES AGAINST RFC 9002 AND NEVER AGAINST THE CAPTURE. No
endpoint this project can reach observes any of these knobs: the perk string's
four segments are h3 SETTINGS, pseudo-header order, transport parameters in wire
order and CID lengths, and not one of them is a timing field. So a `match` here
says "this build does what RFC 9002 says" and says nothing whatever about
Chromium. The third column is the list of what task A3-14 must go and capture,
and it is the most valuable thing on this page.

EVERY CELL IS READ OFF LIVE RECOVERY STATE OR OFF AN EMITTED FRAME. Describe's
signature does not admit a spec of any kind, so no row here can be a restatement
of what a caller typed in.

## Notes

A MISMATCH HERE IS ABOUT THIS BUILD AND NOT ABOUT CHROMIUM. The rows score what
this connection did against what the RFC 9002 extracts in
docs/superpowers/specs/reference-captures/ state. A row reading MISMATCH means
this build deviates from the RFC - which a caller reproducing a non-conforming
client may want deliberately - and a row reading match means nothing more than
conformance.

AN UNEXERCISED ROW SCORES MISMATCH, DELIBERATELY. `not-witnessed-by-this-recording`
never equals a cited figure, so a change that stops driving one of these episodes
turns its row red. The alternative - a fourth verdict value for "not exercised" -
would let a row go quiet, and a quiet row in a fingerprint readout is the failure
mode this whole subsystem exists to avoid.

THE THIRD COLUMN IS TIED TO docs/FINGERPRINT-KNOBS.md AND NOT CHOSEN HERE. A row
is third-column exactly when that file marks its knob UNVERIFIED or PLACEHOLDER.
Seven rows qualify: initial_rtt (markers 5, 13),
initial_congestion_window_bytes (3, 6, 8), congestion_controller (2, 9),
ack_policy (10), ack_range_limit (the PLACEHOLDER table),
pacing_burst_datagrams (7, 11) and pacing_interval_scale (knob 15, added by
task A3-11 while this readout was being built). The plan's sentence names five
of those seven; the two it omits are initial_rtt's invented range and
AckRangeLimit, and both are marked in the tree.

FINGERPRINT-KNOBS' OWN MARKER COUNT WAS STALE BY THREE FOR THREE COMMITS, AND
IS NOT ANY MORE. That file stated 13 markers and tabulated thirteen. It returned
13 at 2769d10 and ebdcc89 and 16 at c9a86cb: task A3-11 added markers for
PacingIntervalScale in TlsQuicRecoverySpec.cs, for the send gate in
TlsQuicApplicationSendPath.cs, and a second in TlsQuicRecoverySpec.cs, without
moving the count. The table now reads 20 hits of which 16 mark a value - the
other four are this file talking ABOUT the marker word - and carries rows 14-16
for the three it had been missing.

THE EPISODE IS LEFT RENDERED HERE RATHER THAN DELETED, because it is the whole
argument for the discriminator above. For three commits this readout and that
table disagreed about the same set, and the readout was right BECAUSE it counts
markers in the source rather than rows in a document. A rule that only ever
agrees with the document it is checked against has never been tested.

THE LAST TWO ROWS ARE OBSERVATIONS AND NOT KNOBS, which is why the table is
longer than the knob list by exactly two. They exist because a knob's SETTING and
the behaviour in force can agree BY ACCIDENT, and AckPolicy is the worked example:
for as long as nothing read TlsQuicRecoverySpec.AckPolicy, `Immediate` and an
observed immediate ACK agreed for no reason at all, and only the second-to-last
pair of rows could say so.

TASK A3-13 WIRED IT, AND THE ROWS ARE WHAT SHOWED THE DIFFERENCE. The reader is
TlsQuicAckTracker.IsWithheldAt; the behaviour-in-force row MOVED when the knob
moved, which is the whole claim, and it moved without a line of the measurement
changing. A row that renders the same string whether or not the knob is read
would have said nothing on either side of that commit.
