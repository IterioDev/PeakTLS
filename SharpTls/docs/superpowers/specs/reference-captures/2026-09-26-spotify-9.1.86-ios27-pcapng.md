# Reference capture: Spotify 9.1.86.2428 on iOS 27.0, passive pcapng with device key log

Everything below is read from `phone.fixed.pcapng` + `keys.txt` (kept outside the repo; SHA-256 of
the pcapng `ceb85340d8f55832b6f756214037bef4e6c88c9e3aa9c81209d746a963c4302d`, of the key log
`5059dcf90eda8b51f8729af603795935fdf913380eb188a47bd3d9b0406e6d09`). Captured 2026-09-26 on
iPhone17,2, iOS 27.0 (24A437), CFNetwork 3896.100.1.2.1, locale en-GB, Europe/Athens. The key
log covers the TCP sessions as well as QUIC, so the HTTP/2 and HTTP/3 layers both decrypt —
the first capture in this repository where that is true. The accompanying third-party report
(`TLS_QUIC_HTTP3_Forensic_Report.md`) covers only the ClientHellos and a summary of HTTP/3; the
numbers here go past it and correct it where they disagree.

Where this document says "measured", the tshark recipe at the end reproduces it.

## 2. TCP ClientHello (app stack)

Identical in all 10 app-stack TCP hellos:

- TLS 1.3 trio `0x1302, 0x1303, 0x1301` — the QUIC order. The transcribed record the profile
  came from had `0x1302, 0x1301, 0x1303`; wrong.
- Cipher list: `GREASE, 1302, 1303, 1301, c02c, c030, c02b, cca9, c02f, cca8, c00a, c009,
  c014, c013`.
- Extensions `GREASE, 0, 23, 65281, 10, 11, 16, 5, 13, 18, 51, 45, 43, 27, GREASE`; payload
  lengths status_request 5, compress_certificate 3 (zlib), renegotiation_info 1,
  ec_point_formats 2, SCT 0, extended_master_secret 0, first GREASE extension 0, second 1.
- Groups `GREASE, 0x11ec, 0x001d, 0x0017, 0x0018, 0x0019`; key shares GREASE 1 byte,
  X25519MLKEM768 1216, X25519 32 (key_share 1263 bytes).
- Signature algorithms `0403 0804 0401 0503 0805 0805 0501 0806 0601 0201` (0805 twice).
- supported_versions `GREASE, 0x0304, 0x0303`; record-layer version 0x0301.
- GREASE classes: supported_groups == key_share in 14 of 14 exactly-listed hellos; cipher,
  supported_versions and the two extension slots independent.

Codebase: trio corrected in `Spotify918602428IOS270Tcp`.

## 3. HTTP/2 preface and framing

Measured on 10 of 10 app-stack connections.

| | App stack |
|---|---|
| SETTINGS, in order | `2:0, 4:2097152, 3:100, 9:1` |
| WINDOW_UPDATE increment | `10485760` |
| Pseudo-header order | `m,s,p,a` |
| First record | SETTINGS + WINDOW_UPDATE + first HEADERS in ONE TLS record |
| SETTINGS ack | own record, after the server's SETTINGS arrive |
| PRIORITY frames / HEADERS priority flag | none / never |

`9` is RFC 9218 `SETTINGS_NO_RFC7540_PRIORITIES`. No `HEADER_TABLE_SIZE`, `MAX_FRAME_SIZE`,
`MAX_HEADER_LIST_SIZE`, `ENABLE_CONNECT_PROTOCOL`. The transcribed record's seven settings and
`15663105` increment were wrong. Codebase: `Spotify918602428IOS270Http2` sends this.

## 4. HPACK encoder policy (app stack)

From `http2.header.repr` on every app-stack request:

- `:method`, `:scheme`: indexed static.
- `:path`, `content-length`, `if-none-match`: literal WITHOUT indexing, static name reference.
- `authorization`: literal NEVER indexed, static name reference.
- Everything else: literal with incremental indexing on first use (static name reference where
  the name is in the static table, new name otherwise), indexed from the dynamic table on the
  next request that repeats the pair.
- No dynamic table size update is sent; the table stays at the 4096 default.

This is nghttp2's default deflater behaviour (its no-index list is `:path, age, content-length,
etag, if-modified-since, if-none-match, location, set-cookie`); only the three names the
capture shows are declared in the preset. Huffman on/off per string was not extracted for h2.

## 5. HTTP/2 header images (app stack)

`gew1-spclient.spotify.com` (streams 145, 146), which is the same header map the h3 leg uses:

```
POST: content-type, spotify-app-version, accept, authorization, time-zone, app-platform,
      priority, accept-encoding, accept-language, content-length, user-agent, x-client-id,
      client-token
GET:  spotify-app-version, accept, authorization, time-zone, app-platform, priority,
      accept-language, accept-encoding, user-agent, x-client-id, client-token
```

## 6. QUIC and HTTP/3 (`spclient.wg.spotify.com`, conns 61, 80, 81)

Handshake and transport parameters agree with `Spotify918602428IOS270Http3` byte for byte:
trio `1302, 1303, 1301`, empty session id, seven parameters in a cyclic rotation with
`0xff080808 = 9` pinned last (offsets seen: `6-7-9-14-15-4-5`, `9-14-15-4-5-6-7`,
`14-15-4-5-6-7-9`, `4-5-6-7-9-14-15`, `7-9-14-15-4-5-6`). Two of nine Spotify QUIC hellos
(conns 84, 85) carry `0x5600` (TLS_FALLBACK_SCSV) after the trio; not investigated.

### Control stream (client uni stream 2), one STREAM frame, 25 bytes, packet number 0

```
00                      stream type: control
04 16                   SETTINGS, length 22
01 7fff                 QPACK_MAX_TABLE_CAPACITY = 16383   (2-byte varint)
07 4064                 QPACK_BLOCKED_STREAMS = 100        (2-byte varint)
c000001e137e86cf        reserved id, 0x1f*N+0x21, N < 2^32 (8-byte varint)
c000000051818a9c        its value, < 2^32                  (8-byte varint)
```

Nothing else is ever sent on the control stream. Server's SETTINGS in reply: `1=4096, 7=16,
8=1, 0x21=1`.

### Stream open timing — NOT "three streams at once"

| Packet number | Stream | Content |
|---|---|---|
| 0 | 2 (control) | SETTINGS, alone in its packet |
| 1 | 0 (request) | first HEADERS, static-only |
| after the server's SETTINGS arrive (pn 5–6) | 6 (encoder) | `02` + Set Dynamic Table Capacity 4096, 4 bytes, one frame |
| when the first Insert Count Increment is due (pn 15 / 28) | 10 (decoder) | `03` + ICI |

The decoder stream opens lazily, on the first instruction it has to carry. SharpTls opens
control, encoder and decoder together; that is a visible difference.

### QPACK encoder policy (decoded with `scripts/qpack_decode.py`)

- Capacity 4096 — equal to the server's advertised maximum, so the client's own ceiling may be
  higher; a capture against a server advertising more would settle it.
- Requests sent before the server's SETTINGS arrive are static-only (prefix `00 00`), and so is
  the FIRST request encoded after the capacity instruction goes out — stream 4 in conns 61 and
  80, stream 84 in conn 81 (whose first 22 requests all left before the server's SETTINGS).
  From the second post-capacity request on, the encoder inserts and the same section
  references the new entries with post-base indices (`EncRIC=10, S=1, Delta=8, Base=0`);
  later sections use relative indices (`Base=9`). 3 of 3 connections.
- WHAT GETS INSERTED IS FREQUENCY-GATED, AND THE COUNTER STARTS WITH THE TABLE. A (name,
  value) pair is inserted the first time it is encoded after having appeared in an earlier
  request that was itself encoded while the table was active; requests encoded before the
  capacity instruction do not count. That one rule explains all 36 inserts and every
  non-insert: the first request after capacity is static-only because nothing has an active
  prior use yet; conn 61's nine pairs common to streams 4 and 8 insert on stream 8, while its
  `content-type: application/protobuf` and `:path /remote-config-resolver/…` (streams 0 and
  8 only) never insert; `accept: application/protobuf` (streams 0, 8, 16) inserts on 16;
  `:path /signup/public/v2/account/validate` (16, 20) inserts on 20. Pairs seen once are
  never inserted. Inserts go out in request-header order, in one encoder-stream frame per
  request that triggers any, in the packet before that request's HEADERS.
- Exact static matches (`:method`, `:scheme`, `accept: */*`, `accept-encoding: gzip, deflate,
  br`, `content-type: application/x-www-form-urlencoded`) are indexed static and never
  inserted. Everything else is eligible, `:path` and `content-length` included — unlike this
  client's h2 encoder. Insert With Name Reference to the static name where the name is in the
  static table (`:authority`, `:path`, `content-type`, `content-length`, `accept`,
  `accept-language`, `user-agent`, `authorization` — the bearer token, 347 Huffman bytes);
  Insert With Literal Name otherwise (`spotify-app-version`, `time-zone`, `app-platform`,
  `priority`, `x-client-id`, `client-token`).
- Two header VALUE images on one host: conns 61 and 80 send `user-agent: Spotify/9.1.86
  iOS/27.0 (iPhone17,2)` and `accept-language: en-GB,en;q=0.9`; conn 81 sends `user-agent:
  Spotify/9.1.86.2428 iOS/Version 27.0 (Build …)` and `accept-language: en-GR;q=1.00`. Two
  HTTP clients inside the app, same QUIC and QPACK shape.
- Huffman only when strictly shorter: `app-platform: iOS` and `content-length: 40` go raw
  (`H=0`); `content-length: 150` goes Huffman (2 bytes vs 3).
- Field lines: exact static match → indexed static; name in static, value not → literal with
  static name reference; after insertion → indexed dynamic. Never-indexed bit unused.
- Decoder stream: Insert Count Increment then Section Acknowledgements (`03 06 84 88 8c …`).

Reproduced by `TlsQuicQpackEncoderPolicy` (design:
`docs/superpowers/specs/2026-09-27-qpack-dynamic-table-encoder-design.md`) behind
`TlsQuicHttp3Spec.QpackEncoderDynamicTableCapacity`, `QpackInsertPolicy` and
`UnidirectionalStreamOpening`; the Spotify presets set all three. Still unmeasured: what the
client announces against a server whose maximum exceeds 4096, and any draining behaviour
near eviction.

## 7. Recipes

```
T='/c/Program Files/Wireshark/tshark.exe'; K=keys.txt; P=phone.fixed.pcapng
# TCP hellos: stream, SNI, suites
"$T" -r $P -Y 'tls.handshake.type==1 && tcp' -T fields -e tcp.stream -e tls.handshake.extensions_server_name -e tls.handshake.ciphersuite
# h2 preface per stream (client side)
"$T" -r $P -o tls.keylog_file:$K -Y 'ip.src==10.0.0.1 && (http2.type==4 || http2.type==8)' -T fields -e tcp.stream -e http2.type -e http2.settings.id -e http2.settings.initial_window_size -e http2.settings.max_concurrent_streams -e http2.settings.no_rfc7540_priorities -e http2.window_update.window_size_increment
# h2 header names and HPACK representations
"$T" -r $P -o tls.keylog_file:$K -Y 'ip.src==10.0.0.1 && http2.type==1' -T fields -e tcp.stream -e http2.streamid -e http2.header.name -e http2.header.repr
# QUIC client stream data for the QPACK decoder
"$T" -r $P -o tls.keylog_file:$K -Y 'ip.src==10.0.0.1 && quic.stream.stream_id' -T fields -e quic.connection.number -e frame.number -e quic.packet_number -e quic.stream.stream_id -e quic.stream.fin -e quic.stream_data > quic_streams.tsv
python scripts/qpack_decode.py quic_streams.tsv      # needs: pip install hpack
```
